# מערכת ניהול הגן – שלב 1: תכנון מעבר ל-Supabase ול-PWA

מסמך זה מסכם את בדיקת הקוד הקיים, את מבנה מסד הנתונים וההרשאות, את תוכנית המעבר ואת מה שנדרש כדי להפעיל את המערכת באייפון של כל הצוות.
בשלב זה **לא בוצעה שום פעולה בפרויקט Supabase**, לא הועלו נתונים, ולא פורסם דבר.

---

## 1. בדיקת הקוד הקיים

| נושא | המצב היום | מה משתנה |
|---|---|---|
| אחסון | כל הנתונים בקובץ JSON אחד ב-localStorage של הדפדפן | טבלאות ב-Supabase, משותפות לכל הצוות |
| התחברות | בחירת שם + קוד (1234 / 1111), הקודים שמורים גלויים בדפדפן | Supabase Auth: אימייל וסיסמה לכל עובדת |
| הרשאות | נאכפות רק בממשק | נאכפות במסד הנתונים (RLS), גם אם מישהו עוקף את הממשק |
| שעון נוכחות | לפי השעון של הטלפון (אפשר לזייף) | לפי שעון השרת בלבד |
| שכר לשעה | שדה בכרטיס העובדת | טבלה נפרדת שרק המנהלת רואה, עם היסטוריית תעריפים |
| יומן פעולות | נכתב על ידי הדפדפן | נכתב אוטומטית במסד הנתונים, ואי אפשר למחוק או לשנות אותו |
| נתוני הדגמה | נטענים אוטומטית בפעם הראשונה | יוסרו מהמערכת האמיתית |
| הגנה מפני הזרקת קוד | כל טקסט עובר `esc()` לפני הצגה – תקין | נשאר |
| עיצוב ומסכים | 14 מסכים, עברית, RTL, מותאם לטלפון, מצב כהה | נשארים כמו שהם |

**חשוב:** המאגר `jojobok/Scanner` הוא **ציבורי**. קוד ה-CRM גלוי כרגע לכל אחד. אין בו נתונים אמיתיים או סודות, אבל לפני חיבור למערכת האמיתית צריך להעביר אותו למאגר פרטי (סעיף 9).

## 2. מבנה מסד הנתונים

קבצי ההקמה נמצאים ב-`gan-crm/supabase/migrations/` (4 קבצים, לפי סדר):

| קובץ | תוכן |
|---|---|
| `20261106100000_core_schema.sql` | סוגי נתונים ו-15 טבלאות |
| `20261106100100_helpers_triggers_functions.sql` | פונקציות עזר, טריגרים, פונקציות שרת (שעון, שכר, הודעות) |
| `20261106100200_rls_policies.sql` | הרשאות: Row Level Security לכל טבלה |
| `20261106100300_realtime_and_defaults.sql` | עדכונים חיים + 4 הכיתות + שורת הגדרות (בלי אנשים) |

### הטבלאות

| טבלה | מה יש בה |
|---|---|
| `garden_settings` | שם הגן (שורה אחת) |
| `classes` | 4 הכיתות: שם, גיל, תפוסה, צבע |
| `staff` | עובדות: שם, אימייל, תפקיד (מנהלת / גננת / סייעת), כיתה, טלפון, פעילה |
| `staff_pay_rates` | שכר לשעה + מאיזה תאריך הוא תקף (מנהלת בלבד) |
| `children` | שם, כיתה, אלרגיות, פעיל |
| `child_private` | תאריך לידה, שני הורים וטלפונים, הערות (מידע רגיש) |
| `child_attendance` | נוכח / נעדר לכל ילד בכל יום, מי סימנה ומתי |
| `shifts` | כניסה ויציאה של עובדות, משמרות ידניות, סימון "לבדיקה" |
| `daily_reports` | דוח יומי לכיתה: כמות ילדים, סיכום, ארוחות, אירועים |
| `complaints` | תלונות הורים: סטטוס, עדיפות, אחראית, אופן טיפול |
| `schedule_items` | סדר יום לכל כיתה |
| `messages` + `message_recipients` | הודעות מהמנהלת, ולכל נמענת: מתי קראה |
| `reminders` | תזכורות מהצוות למנהלת, תשובה וסטטוס |
| `audit_log` | יומן פעולות: מי שינה מה, מתי, ערך לפני ואחרי |

### פונקציות שרת

| פונקציה | למה |
|---|---|
| `clock_in()` / `clock_out()` | כניסה ויציאה לפי שעון השרת. משמרת שנשארה פתוחה מעל 16 שעות נסגרת עם 0 שעות ומסומנת לבדיקת המנהלת |
| `payroll_report(חודש)` | דוח שכר: שעות × התעריף שהיה תקף בכל יום. מנהלת בלבד |
| `send_message(...)` | שליחה לכולם, לגננות, לסייעות, לצוות כיתה או לעובדת אחת |
| `mark_message_read(...)` | "קראתי" – רק עבור העובדת עצמה |
| `replace_class_schedule(...)` | שמירת סדר יום שלם בפעולה אחת |
| `link_my_account()` | בכניסה הראשונה, מחבר את המשתמשת לכרטיס העובדת לפי האימייל |
| `staff_directory()` | שמות ותפקידים של הצוות (בלי טלפונים ואימיילים) |
| `log_event(...)` | רישום אירועים כמו כניסה למערכת |

## 4. תוצאות הבדיקות המקומיות

הרצתי את קבצי ההקמה על מסד נתונים מקומי וזמני (PostgreSQL 16), עם חיקוי של מערכת ההתחברות של Supabase ועם **אנשים בדיוניים בלבד**.

**94 בדיקות, 94 עברו.** בין השאר נוסו פעולות לא מורשות, וכולן נחסמו:
- משתמש לא מחובר מנסה לקרוא ילדים, עובדות ושכר
- אדם זר שנרשם מנסה להוסיף את עצמו כמנהלת
- עובדת לשעבר מנסה להחתים כניסה
- גננת מנסה לקדם את עצמה למנהלת, לעבור כיתה, לראות שכר, לסמן נוכחות בכיתה אחרת, לסמן נוכחות 10 ימים אחורה, ולהכניס משמרת עם שעות מזויפות
- סייעת מנסה לראות פרטי הורים, לכתוב דוח יומי, לערוך סדר יום, לשנות נושא של תלונה, ולסמן "קראתי" בשם אחרות
- המנהלת מנסה לערוך או למחוק את יומן הפעולות

נבדקו גם: חישוב שכר עם העלאת שכר באמצע החודש (720 ₪ כצפוי), זיהוי התנגשות עריכה, וחיבור עובדת חדשה בכניסה הראשונה.

הרצה חוזרת: `gan-crm/supabase/tests/run_local_tests.sh`. הקבצים בתיקיית `tests/` מיועדים רק למסד מקומי, **ואסור להריץ אותם על הפרויקט האמיתי**.

> הבדיקות רצו על חיקוי של Supabase ולא על Supabase עצמו. לפני העלייה לאוויר צריך להריץ אותן שוב על פרויקט בדיקה נפרד ב-Supabase.

## 5. התחברות

- **אימייל + סיסמה** לכל עובדת (מומלץ). "קישור קסם" באימייל לא מתאים לאייפון: הוא נפתח ב-Safari ולא באפליקציה שבמסך הבית, והאפליקציה לא תהיה מחוברת.
- **ההרשמה החופשית תכובה.** רק מי שהמנהלת הזמינה יכולה להיכנס.
- **הוספת עובדת:** המנהלת מוסיפה אותה במערכת עם האימייל, ושולחת לה הזמנה מלוח הבקרה של Supabase. בשלב מאוחר יותר אפשר להוסיף כפתור "הזמנה" בתוך האפליקציה (דורש Edge Function, כדי שהמפתח הסודי יישאר בשרת).
- **אימות דו-שלבי** (קוד מאפליקציית אימות) מומלץ למנהלת.
- **שליחת אימיילים:** שירות השליחה המובנה של Supabase מוגבל מאוד ומיועד לבדיקות. צריך לחבר שירות שליחה (SMTP) משלך, למשל Resend.
- **טלפון שאבד:** המנהלת מסמנת את העובדת כלא פעילה, והגישה נחסמת מיד.

## 6. תוכנית המעבר מ-localStorage ל-Supabase

### 6.1 שינויים בקוד האפליקציה
1. **שכבת נתונים חדשה** (`data.js`): במקום `db` בזיכרון ו-`save()`, כל מסך טוען מהשרת רק את מה שהוא צריך ושומר כל שינוי בנפרד. העיצוב והמסכים נשארים.
2. **ספריית `supabase-js`** נשמרת כקובץ בתוך הפרויקט, כדי שהאפליקציה לא תלויה באתר חיצוני.
3. **מסך כניסה חדש** (אימייל וסיסמה, "שכחתי סיסמה") במקום בחירת שם וקוד.
4. **הסרת:** קודי 1234 / 1111, נתוני ההדגמה האוטומטיים, ושמירת הנתונים ב-localStorage.
5. **עדכונים חיים:** מינוי ל-Supabase Realtime, כך שנוכחות, הודעות ותזכורות מתעדכנות אצל כולן תוך שניות, לפי ההרשאות.
6. **מחיקת ילד או עובדת** תוחלף ב"העברה לארכיון", כדי שלא יאבד מידע היסטורי.

### 6.2 התנגשויות עריכה ומניעת אובדן מידע
- בכל רשומה שאפשר לערוך יש **מספר גרסה**. השמירה מצליחה רק אם אף אחת לא שינתה את הרשומה בינתיים. אחרת מופיעה הודעה: "הדוח עודכן על ידי … – לטעון את הגרסה החדשה?", והטקסט שהקלדת לא נמחק.
- **נוכחות:** כל סימון נשמר מיד, והסימון האחרון קובע. נשמר מי סימנה ומתי.
- **דוח יומי:** אחד לכל כיתה ליום (נאכף במסד).
- **שמירה שנכשלה** (אין רשת או שגיאה): החלון נשאר פתוח עם מה שהוקלד, ויש כפתור "נסי שוב".
- **שעון נוכחות** פועל רק כשיש חיבור, כי השעה נקבעת בשרת.

### 6.3 העברת נתונים קיימים (אם הוזנו נתונים אמיתיים בגרסה המקומית)
- המנהלת מורידה גיבוי מהגרסה הקיימת.
- כלי ייבוא חד-פעמי, למנהלת בלבד, קורא את הגיבוי ומכניס אותו לטבלאות. הקודים הישנים לא מועברים.
- התאמת השדות:

| בגיבוי הישן | בטבלה החדשה |
|---|---|
| `classes` | `classes` (התאמה לפי שם הכיתה) |
| `staff` (בלי `pin`) | `staff` + `staff_pay_rates` (התעריף הנוכחי מתאריך תחילת העבודה) |
| `children` | `children` + `child_private` |
| `childAttendance[תאריך][ילד]` | `child_attendance` |
| `shifts` (תאריך + שעה) | `shifts` (מומר לשעון ישראל) |
| `reports`, `complaints`, `reminders` | הטבלאות המקבילות |
| `messages` + `readBy` | `messages` + `message_recipients` |
| `schedules` | `schedule_items` |
| `log` | `audit_log` (כאירועים היסטוריים) |

## 7. התאמה לאייפון (PWA)

| רכיב | מה צריך |
|---|---|
| `manifest.webmanifest` | שם "ניהול הגן", `lang: he`, `dir: rtl`, פתיחה במסך עצמאי (`standalone`), צבעים, אייקונים |
| אייקונים | אייקון מעוצב: 180×180 לאייפון, 192 ו-512, וגרסה למסגרת עגולה |
| תגיות לאייפון | `apple-touch-icon`, `apple-mobile-web-app-capable`, צבע שורת סטטוס, שם קצר |
| `sw.js` (service worker) | שומר במטמון **רק את קבצי האפליקציה** (HTML, CSS, JS, אייקונים). **שום מידע של ילדים או עובדות לא נשמר במטמון** |
| הודעת "אין חיבור" | פס בולט בראש המסך: "אין חיבור לאינטרנט. אי אפשר לשמור שינויים עד שהחיבור יחזור". כפתורי השמירה מושבתים |
| שמירת התחברות | ההתחברות נשמרת בתוך האפליקציה. תוקף הגישה קצר ומתחדש אוטומטית. "יציאה" מוחקת את ההתחברות ואת כל המידע שבזיכרון |
| כותרות אבטחה | CSP שמתיר חיבור רק לכתובת ה-Supabase של הגן, ומניעת הטמעה באתרים אחרים |
| אחסון באינטרנט | אתר עם HTTPS (ראו סעיף 11) |

מגבלות של אייפון שכדאי להכיר:
- מתקינים דרך **Safari → שיתוף → "הוסף למסך הבית"**.
- לאפליקציה שבמסך הבית יש אחסון נפרד מ-Safari, ולכן מתחברים מתוך האפליקציה עצמה.
- התראות Push באייפון אפשריות (iOS 16.4 ומעלה) רק לאפליקציה שהותקנה במסך הבית. זו תוספת אפשרית לשלב מאוחר יותר.

## 8. אבטחה וגיבויים

### אבטחה
- בדפדפן נמצא רק **המפתח הציבורי** (anon / publishable) של Supabase, שמיועד לכך. ההגנה על המידע היא ה-RLS.
- **המפתח הסודי (service_role) לא יופיע בקוד, בדפדפן או ב-GitHub**, אף פעם.
- אין סיסמאות בקוד. כל עובדת בוחרת סיסמה בעצמה דרך הזמנה באימייל.
- את מפתח החיבור ואת כתובת הפרויקט מכניסים בהגדרות האחסון באינטרנט, לא ב-GitHub.

### תוכנית גיבוי ושחזור
1. **גיבוי יומי אוטומטי** של Supabase (בתוכנית Pro, נשמר 7 ימים).
2. **גיבוי חודשי ידני** של בעל המערכת (ייצוא מלא של המסד), שנשמר מוצפן במקום פרטי. **לא ב-GitHub ולא במייל רגיל.**
3. **ייצוא מתוך האפליקציה** למנהלת, כגיבוי נוסף.

## 10. הנחיות לשמירת פרטיות המידע

- **רק מה שצריך:** לא לשמור מספרי תעודת זהות, כתובות או מידע רפואי מעבר לאלרגיות והערות הכרחיות.
- **יידוע ההורים:** הודעה כתובה להורים על המידע שנשמר, למה, מי רואה אותו, ולכמה זמן.
- **גישה לפי תפקיד:** סייעות לא רואות פרטי הורים (אפשר לשנות לפי החלטתך).
- **טלפונים:** נעילה בקוד או ב-Face ID בכל טלפון שמשמש לעבודה. לא לצלם מסכים ולא להעביר פרטי ילדים בוואטסאפ.
- **עובדת שעוזבת:** מסמנים אותה כלא פעילה באותו יום.
- **טלפון שאבד:** מסמנים את העובדת כלא פעילה, ומחליפים לה סיסמה.
- **משך שמירה:** לקבוע כמה זמן נשמרים פרטי ילד אחרי שעזב (למשל שנה) ומתי מוחקים רשומות ישנות מיומן הפעולות.
- **מיקום השרת:** לבדוק באיזה אזור נוצר הפרויקט ב-Supabase (Settings → General). עדיף אזור באירופה. אי אפשר לשנות אזור אחרי שהפרויקט נוצר.
- **ייעוץ משפטי:** בישראל חלים חוק הגנת הפרטיות (כולל תיקון 13, בתוקף מאוגוסט 2025) ותקנות אבטחת מידע. כדאי לבדוק עם עורך דין לפרטיות אילו חובות חלות על הגן. זה לא ייעוץ משפטי.
